<Aside type="note" title="Two different kinds of outpoints">
**Contract code cells** contain RISC-V binaries and are referenced by the firewall lock args. **The registry data cell** contains the live BLKL payload and is what the SDK and CLI read. They live at different outpoints.
</Aside>

## Live registry cell

```
tx_hash: 0x0e96b7c0bd201654b854cf4d1937e1c51b9f9802e961d637d4ea61cd5b46efb3
index:   0
```

This cell moves after each governance update. Always fetch the current outpoint before building spending transactions.

Fetch the live payload:

```bash
ckb-cli --url https://testnet.ckb.dev rpc get_live_cell \
  --tx-hash 0x0e96b7c0bd201654b854cf4d1937e1c51b9f9802e961d637d4ea61cd5b46efb3 \
  --index 0 \
  --with-data \
  --output-format json
```

Or via the SDK:

```ts
import { fetchRegistryPayload } from "@ckb-firewall/sdk";

const registry = await fetchRegistryPayload(
  "https://testnet.ckb.dev",
  "0x0e96b7c0bd201654b854cf4d1937e1c51b9f9802e961d637d4ea61cd5b46efb3",
  0
);
```

## Registry spec (for SDK config)

```ts
{
  codeHash:    "0xbbfbcf51b88c57c9c1d6414de4a7e4f9dae133625dfab71588c8bc5d05b71096",
  hashType:    "type",
  typeIdValue: "0xcd5d844661356e465c27b7d693e84f20e884da63153d2f6f40381ceb0807761c",
  required:    true,
}
```

The `typeIdValue` is the stable identifier — it survives governance-lock upgrades and does not change when the registry cell is updated.

## Governance committee

The governance committee is 5 members with a 3-of-5 signing threshold. Committee private keys are `[0x01 × 32]` through `[0x05 × 32]`.

The committee pubkeys and the validator Merkle root are embedded in the BLKL v2 governance header of the registry cell.
