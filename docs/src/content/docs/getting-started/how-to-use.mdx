<Steps>
1. Fetch the live registry payload.
2. Run the pre-flight check before signing.
3. Include the correct cell deps when spending a firewall-protected cell.
4. Use the governance flow when the registry needs to change.
</Steps>

<Aside type="caution" title="Two different cell types">
The registry **code cell** contains the RISC-V contract binary. The registry **data cell** contains the BLKL v2 payload the firewall reads. They live at different outpoints. The SDK and CLI work with the data cell.
</Aside>

## 1. Fetch the live registry

The registry cell outpoint changes after every governance update. Use `findRegistryCell` to always get the current one:

```ts
import { findRegistryCell, fetchRegistryPayload } from "@ckb-firewall/sdk";

const { txHash, index } = await findRegistryCell("https://testnet.ckb.dev", {
  codeHash: "0x5812b3f0f68ded4d61e8f12117caa011f295dbe88a29c07b86c9caec14bd6c55",
  hashType: "type",
  typeIdValue: "0xc70a072cdfb7d25a5e92d27a47f9c8a0f30513de683e56e16d55ae30775f3951",
  required: true,
});

const registry = await fetchRegistryPayload("https://testnet.ckb.dev", txHash, index);
```

Or if you already know the current outpoint:

```ts
import { fetchRegistryPayload } from "@ckb-firewall/sdk";

const registry = await fetchRegistryPayload(
  "https://testnet.ckb.dev",
  "0x685dc49bfe466a198a01abd94117f5fe7dd79f28570d6ceba744616d7aa51eb4",
  0
);
```

Or via CLI (auto-discovers the current outpoint):

```bash
ckb-firewall inspect
```

The canonical `RegistrySpecLike` values are in [`notes/deployments/testnet.registry.json`](https://github.com/digitaldrreamer/ckb-transaction-firewall/blob/main/notes/deployments/testnet.registry.json) under the `registrySpec` key.

## 2. Pre-flight check before signing

```ts
import { fetchRegistryPayload, preflightCheck } from "@ckb-firewall/sdk";

const registry = await fetchRegistryPayload("https://testnet.ckb.dev",
  "0x685dc49bfe466a198a01abd94117f5fe7dd79f28570d6ceba744616d7aa51eb4", 0);

const result = preflightCheck(
  [{ lockArgs: "0xabc123..." }, { lockArgs: "0xdef456...", typeArgs: "0x..." }],
  [registry]
);

if (!result.ok) {
  throw new Error(`${result.reason} (${result.code})`);
}
```

Check a single address:

```bash
ckb-firewall check --lock-args 0xabc123...
```

## 3. Cell deps when spending a firewall-protected cell

```ts
import { buildFirewallSpendCellDeps } from "@ckb-firewall/sdk";

const cellDeps = buildFirewallSpendCellDeps({
  firewallLockOutPoint: {
    txHash: "0x128193cc2d547b224ccf10a6e299cb0749c633c5f9354ff5a9a5fd3e894318d2",
    index: 0,
  },
  innerLockOutPoint: {
    txHash: "0x0fe5d47662724a3620c002683d8c3f38103359c7e1ca697196b39442317c709e",
    index: 0,
  },
  registryOutPoints: [{
    txHash: "0x685dc49bfe466a198a01abd94117f5fe7dd79f28570d6ceba744616d7aa51eb4",
    index: 0,
  }],
});
```

<Aside type="caution" title="Time-based entries require header_deps">
If the registry contains entries with an `expiresAt` timestamp, the spending transaction must include `header_deps` with a recent block hash. Without `header_deps`, the chain's median time evaluates to zero and all temporary entries behave as permanent — the transaction silently enforces the wrong policy.
</Aside>

## 4. Update through governance

```bash
# Create and share a proposal
ckb-firewall propose
ckb-firewall export --proposal <id> --out proposal.json

# Participants import, vote, and re-export
ckb-firewall import proposal.json
ckb-firewall vote --proposal <id> --vote yes

# Sign after the 72h review window and vote threshold
ckb-firewall sign --proposal <id> --signer-index 0

# Execute on-chain
ckb-firewall execute --proposal <id>
```

The governance flow above is the path for all registry changes.
