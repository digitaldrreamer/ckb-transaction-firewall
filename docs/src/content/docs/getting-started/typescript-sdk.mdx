The TypeScript SDK is the application-layer check. It parses `BLKL` v2 registry payloads from matching registry cell deps and rejects outputs that target blacklisted destinations.

Published on npm as [@ckb-firewall/sdk](https://www.npmjs.com/package/@ckb-firewall/sdk).

## Pre-flight check — two approaches

The SDK has two ways to run a pre-flight check. Use the one that fits where you are in the transaction lifecycle.

### `preflightCheck` — before the transaction is fully built

Use this when you want to check a set of outputs against the registry **before assembling the full unsigned transaction**. You fetch the registry payload separately and pass it directly — no cell deps involved.

```ts
import { fetchRegistryPayload, preflightCheck } from "@ckb-firewall/sdk";

const registry = await fetchRegistryPayload(
  "https://testnet.ckb.dev",
  "0x685dc49bfe466a198a01abd94117f5fe7dd79f28570d6ceba744616d7aa51eb4",
  0
);

const decision = preflightCheck(
  [{ lockArgs: "0xdeadbeef..." }],
  [registry]
);

if (!decision.ok) {
  console.error(decision.code, decision.reason);
}
```

### `TransactionFirewall` — once the transaction has cell deps

Use this when you have a partially-built unsigned transaction and the registry is already in `cellDeps`. It resolves the registry from the dep by `typeIdValue` — the same matching logic the on-chain lock uses. This is the safer check for transaction builders because it confirms the same dep that will be broadcast is what was validated.

```ts
import { TransactionFirewall } from "@ckb-firewall/sdk";

const firewall = new TransactionFirewall({
  registries: [
    {
      codeHash: "0x5812b3f0f68ded4d61e8f12117caa011f295dbe88a29c07b86c9caec14bd6c55",
      hashType: "type",
      typeIdValue: "0xc70a072cdfb7d25a5e92d27a47f9c8a0f30513de683e56e16d55ae30775f3951",
      required: true,
    },
  ],
});

const result = firewall.checkTransaction({
  cellDeps: [
    {
      type: { codeHash: "0x5812b3f0...", hashType: "type", args: registryTypeArgs },
      data: registryBlklPayloadHex,
    },
  ],
  outputs: [{ lockArgs: "0x..." }],
});
```

The registry is matched by `typeIdValue` (bytes 34–65 of the 66-byte v2 type args), so `TransactionFirewall` survives governance-lock upgrades without any config change.

## Finding the current registry outpoint

The registry cell outpoint changes on every governance update. If you don't have a reliable way to track it, use `findRegistryCell` to discover it from the CKB indexer:

```ts
import { findRegistryCell, fetchRegistryPayload } from "@ckb-firewall/sdk";

const { txHash, index } = await findRegistryCell("https://testnet.ckb.dev", {
  codeHash: "0x5812b3f0f68ded4d61e8f12117caa011f295dbe88a29c07b86c9caec14bd6c55",
  hashType: "type",
  typeIdValue: "0xc70a072cdfb7d25a5e92d27a47f9c8a0f30513de683e56e16d55ae30775f3951",
  required: true,
});

const registry = await fetchRegistryPayload("https://testnet.ckb.dev", txHash, index);
```

`findRegistryCell` queries `get_cells` on the CKB node and filters by `typeIdValue` — so it finds the correct cell regardless of which governance-lock version is current. Requires a CKB node with the built-in indexer enabled (CKB ≥ 0.109; `https://testnet.ckb.dev` supports this).

The canonical `RegistrySpecLike` values for testnet are in [`notes/deployments/testnet.registry.json`](https://github.com/digitaldrreamer/ckb-transaction-firewall/blob/main/notes/deployments/testnet.registry.json) under the `registrySpec` key.

## `fetchRegistryPayload` error handling

`fetchRegistryPayload` throws plain `Error` instances — not typed SDK errors. The cases to handle in production:

| Thrown message contains | Cause | Recovery |
|---|---|---|
| `CKB RPC unreachable` | Network failure or wrong RPC URL | Retry or check connectivity |
| `HTTP <status>` | Node returned non-2xx | Retry or switch node |
| `is not live` | **Registry was updated** — the outpoint you have is consumed | Fetch the new outpoint via `findRegistryCell` |
| `has no data` | Outpoint points at a code cell, not the data cell | Check you are using the registry data cell outpoint |
| `InvalidRegistryData` | Payload parse failed | Registry cell is corrupted or wrong cell entirely |

The `is not live` case is the most common in production — a governance update consumed the cell you cached. Catch it and re-discover the outpoint:

```ts
let registry;
try {
  registry = await fetchRegistryPayload(rpcUrl, cachedTxHash, cachedIndex);
} catch (err) {
  if (err instanceof Error && err.message.includes("is not live")) {
    const { txHash, index } = await findRegistryCell(rpcUrl, registrySpec);
    registry = await fetchRegistryPayload(rpcUrl, txHash, index);
    // persist { txHash, index } to your cache here
  } else {
    throw err;
  }
}
```

## Build a firewall lock script

```ts
import { buildFirewallLockScript } from "@ckb-firewall/sdk";

const lockScript = buildFirewallLockScript({
  firewallCodeHash: "0x8192c9df809976ae9b093dd0d6b072a96101be8cffe61a7e9ac87c04e1f4dc54",
  firewallHashType: "type",
  flags: 0x03,           // check lock_args AND type_args
  registries: [
    {
      codeHash:    "0x5812b3f0...",
      hashType:    "type",
      typeIdValue: "0xc70a072c...",
      required:    true,
    },
  ],
  innerCodeHash: "0x9be62e0423d4278b15c071bb881a4ebf936f7e46b3df0f152de50ae416f54465",
  innerHashType: "type",
  innerArgs:     "0x<20-byte-pubkey-hash>",
});
// { codeHash, hashType, args: "0x..." }
```

## Cell deps for spending a firewall-protected cell

When building a transaction that spends a cell locked by the firewall, include these cell deps:

```ts
import { buildFirewallSpendCellDeps } from "@ckb-firewall/sdk";

const cellDeps = buildFirewallSpendCellDeps({
  firewallLockOutPoint: {
    txHash: "0x128193cc2d547b224ccf10a6e299cb0749c633c5f9354ff5a9a5fd3e894318d2",
    index: 0,
  },
  innerLockOutPoint: {
    txHash: "0x0fe5d47662724a3620c002683d8c3f38103359c7e1ca697196b39442317c709e",
    index: 0,
  },
  registryOutPoints: [
    {
      txHash: "0x685dc49bfe466a198a01abd94117f5fe7dd79f28570d6ceba744616d7aa51eb4",
      index: 0,
    },
  ],
});
// [{ outPoint, depType: "code" }, ...]
```

<Aside type="caution" title="Registry outpoints change on update">
The registry data cell outpoint moves after each governance update. Always use the latest outpoint before building a spending transaction. Use `findRegistryCell` if you don't track updates actively.
</Aside>

<Aside type="caution" title="Time-based entries require header_deps">
If the registry contains entries with an `expiresAt` timestamp, the spending transaction must include `header_deps` with a recent block hash. Without `header_deps`, the chain's median time evaluates to zero — all temporary entries are treated as permanently active and the transaction silently enforces the wrong policy.
</Aside>

## Point checks

To check whether a single lock args or type args is blacklisted without building a full transaction:

```ts
import { isBlacklisted, isTypeArgsBlacklisted } from "@ckb-firewall/sdk";

// Check by lock args (the common case)
const lockBlocked = isBlacklisted("0xdeadbeef...", [registry]);

// Check by type args (when flag bit 1 is set in the firewall lock args)
const typeBlocked = isTypeArgsBlacklisted("0xdeadbeef...", [registry]);
```

Entries with a past `expiresAt` are automatically treated as inactive. Both functions accept multiple registry payloads and check the union of all entries.
