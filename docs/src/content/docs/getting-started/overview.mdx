The firewall prevents a wallet cell from being spent in a transaction that sends to a blacklisted address. It checks your **outputs** — not your counterparties, not incoming payments, not other inputs in the same transaction.

If you want a consensus-layer floor that cannot be bypassed by application code, the firewall lock is what provides it.

<Aside type="tip" title="Design rule">
The lock is the guarantee. The SDK is the fast feedback path. Don't treat them as substitutes.
</Aside>

## Components

| Component | What it does |
|---|---|
| `firewall-lock` | Lock script that runs on every node when a protected cell is spent |
| `blacklist-registry` | Type script governing the BLKL payload cell |
| Registry cell | The live cell whose data contains the sorted blacklist entries |
| `@ckb-firewall/sdk` | TypeScript pre-flight check before signing |
| `@ckb-firewall/cli` | Inspection, testing, and governance tooling |

## Typical flow

1. Build the unsigned transaction
2. Fetch the live registry cell data
3. Run `preflightCheck` — get a structured error before broadcast if blocked
4. Sign and broadcast
5. The firewall lock enforces the same rule again at consensus

## What is enforced

- Blacklisted `lock_args` of outputs
- Blacklisted `type_args` of outputs (when flag bit 1 is set)
- Exactly one matching registry dep (fail-closed on missing or ambiguous)
- Entry sort order and payload structure

## What is not enforced

- Addresses not yet on the blacklist
- Non-address attack vectors
- Incoming payments from blacklisted sources
- Cells that do not use the firewall lock

<Aside type="caution" title="Existing cells are not protected automatically">
Adopting the firewall lock means using a different lock script, which produces a **different CKB address**. Cells at your existing address are unprotected until they are explicitly spent into the new firewall-locked address. There is no in-place upgrade.
</Aside>

## Common entry points

<Tabs>
<TabItem label="CLI">

```bash
npm install -g @ckb-firewall/cli
ckb-firewall inspect
ckb-firewall check --lock-args 0xabc123...
```

</TabItem>
<TabItem label="TypeScript">

```ts
import { fetchRegistryPayload, preflightCheck } from "@ckb-firewall/sdk";

const registry = await fetchRegistryPayload(
  "https://testnet.ckb.dev",
  "0x0e96b7c0bd201654b854cf4d1937e1c51b9f9802e961d637d4ea61cd5b46efb3",
  0
);

const result = preflightCheck([{ lockArgs: "0x..." }], [registry]);
```

</TabItem>
